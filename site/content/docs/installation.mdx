title: Installation
description: Add the audiocn Solid registry to a shadcn project and install components with the shadcn CLI.
---

audiocn Solid is a [shadcn registry](https://ui.shadcn.com/docs/registry). You add components with the same `shadcn` CLI, and the code lands in your project.

## Requirements

- Solid 1.9.15 or later. Solid 2.0.0-rc.13 is an experimental lane, tested with Kobalte 2.0.0-alpha.2.
- Tailwind CSS v4.
- A project set up with shadcn and a `components.json`. audiocn Solid components use the standard shadcn tokens (`background`, `muted`, `primary`, `ring`...) and the `cn` helper from `@/lib/utils`.
- Interactive primitives use Kobalte. The runtime-specific registry installs the matching Kobalte line for you.

### Set up a Solid project

Skip this if your Solid project already has Tailwind v4, the theme tokens below, and a `components.json`. Use this manual Solid setup instead of the React-oriented shadcn initializer.

```bash title="Create the app"
bunx --bun create-vite@9.2.1 audio-app --template solid-ts --no-interactive --no-immediate
cd audio-app
bun add -d tailwindcss@4.3.3 @tailwindcss/vite@4.3.3 typescript@7.0.2
```

Choose one runtime. The stable Solid 1 setup:

```bash title="Solid 1 dependencies"
bun add solid-js@1.9.15
bun add -d vite@7.3.6 vite-plugin-solid@2.11.14
```

The experimental Solid 2 setup:

```bash title="Solid 2 dependencies"
bun remove vite-plugin-solid
bun add solid-js@2.0.0-rc.13 @solidjs/web@2.0.0-rc.13
bun add -d vite@8.3.2 @solidjs/vite-plugin@3.0.0-next.47
```

Replace `tsconfig.json` with the following. Solid 1 uses `"jsxImportSource": "solid-js"`; for Solid 2, change that one value to `"jsxImportSource": "@solidjs/web"`.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "allowImportingTsExtensions": true,
    "jsx": "preserve",
    "jsxImportSource": "solid-js",
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true,
    "paths": { "@/*": ["./src/*"] },
    "types": ["vite/client"]
  },
  "include": ["src"]
}
```

Replace `vite.config.ts` with the matching configuration.

```ts title="Solid 1 vite.config.ts"
import { fileURLToPath, URL } from "node:url";
import solid from "vite-plugin-solid";
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [solid(), tailwindcss()],
  resolve: {
    alias: { "@": fileURLToPath(new URL("./src", import.meta.url)) },
  },
});
```

```ts title="Solid 2 vite.config.ts"
import { fileURLToPath, URL } from "node:url";
import solid from "@solidjs/vite-plugin";
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [solid(), tailwindcss()],
  resolve: {
    alias: { "@": fileURLToPath(new URL("./src", import.meta.url)) },
    dedupe: ["solid-js", "@solidjs/web"],
  },
});
```

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-rhea",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
```

Check the configuration without installing React primitives:

```npm title="Check the CLI configuration"
npx shadcn@4.21.0 info
```

<Step>

### Add the registry

Use the registry URL for the Solid version in your app.

Solid 1:

```json title="components.json"
{
  "registries": {
    "@audiocn-solid": "https://<domain>/r/solid1/{name}.json"
  }
}
```

Solid 2:

```json title="components.json"
{
  "registries": {
    "@audiocn-solid": "https://<domain>/r/solid2/{name}.json"
  }
}
```

</Step>

<Step>

### Add a component

```npm
npx shadcn@4.21.0 add @audiocn-solid/level-meter
```

The CLI copies the component and everything it depends on: the audio core (`lib/audio`), Solid compatibility helpers, audio theme tokens, and any hooks it uses.

</Step>

<Step>

### Use it

```tsx
import { LevelMeter } from "@/components/ui/level-meter";

export const MicLevel = (props: { peakDb: number }) => (
  <LevelMeter aria-label="Microphone level" peakDb={props.peakDb} />
);
```

</Step>

## What gets installed

| Path | What it is |
| --- | --- |
| `components/ui/*` | The components, one file each |
| `hooks/use-*.ts` | Hooks: frame sources, Web Audio, mixer state |
| `lib/audio/*.ts` | The framework-neutral audio core: decibels, ballistics, tapers, types |
| `lib/solid/*.ts` | Small Solid compatibility helpers used by registry files |
| `lib/audiocn-license.txt` | Upstream MIT and Phosphor copyright and permission notices; retain this file when redistributing |
| global CSS | Six audio tokens: `--meter-ok`, `--meter-warn`, `--meter-clip`, `--channel-mute`, `--channel-solo`, `--channel-monitor` |

The paths follow the aliases in your `components.json`, so they adapt to projects with a `src` folder or custom aliases.

## For AI agents

Every component, hook and block page has a **Copy prompt for AI** button. It copies one document with the install steps, usage, API reference, and links to the page examples.

The same document is served at the page URL with `.md` appended, so an agent can fetch it directly:

```bash
curl https://<domain>/docs/components/bar-visualizer.md
```

[llms.txt](/llms.txt) indexes every page, and [llms-full.txt](/llms-full.txt) is the whole documentation in one file.

## Solid 1 and Solid 2

The two registry URLs expose the same public audiocn API. The Solid 1 registry targets Solid 1.9.15+ and the Solid 1 Kobalte line. The Solid 2 registry targets Solid 2 and the Solid 2 Kobalte line. Runtime-specific compatibility files are selected when the registry is built; application code should not branch on the Solid version.

- The six audio tokens land in your global CSS. If your theme already has status colours, point the tokens at them instead (see [Theming](/docs/concepts/theming)).
- The code compiles against an ES2022 `lib`.

## Install everything

Every block pulls in the components it uses. The full mixer installs most of the library in one step:

```npm
npx shadcn@4.21.0 add @audiocn-solid/system-audio-mixer
```
